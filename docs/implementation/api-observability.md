# API correlation and safe response events

D119 adds one shared wrapper to every declared HTTP method in all28 app/api route files. LABSD_API_OBSERVABILITY_ENABLED defaults0; exact1 enables generated X-Request-ID plus structured stdout metadata. Incoming IDs are ignored. Logs include UTC time, request ID, source-code route template, bounded method, status, response/handler_exception outcome and headersReadyMs. No query, URL, route parameter, cookie, auth header, actor, request/response body, error message or stack is logged by this module.

Original Request and context go unchanged to the existing handler. Normal responses preserve status/body/cookies; immutable response headers use a transferred stream with copied headers. Nothing buffers or waits for file completion. headersReadyMs is time until the handler returns response headers, not download duration or browser render time. Unexpected thrown API exceptions become private/no-store generic500 INTERNAL_ERROR, with no retry advice. Expected domain denials continue through their existing response contracts.

Sink uses stdout with no application queue. At64KiB writable backlog it drops an event and increments a bounded counter; next accepted event reports droppedSinceLastWrite. Lines are capped1KiB, fields explicitly selected, synchronous writer/sink errors cannot replace a completed business response. An asynchronous Node stream error is handled and marks that sink terminal-failed; subsequent events are dropped until the sink/process is replaced. No automatic log-delivery recovery is claimed. This is best-effort operational telemetry, not the financial audit ledger or guaranteed delivery. A blocked synchronous OS sink can still stall the process; use a supervised collector with its own bounded policy. Healthy health/ready calls get IDs but omit logs; failed probes remain visible.

Enable consistently by restarting/redeploying selected web instances after collector/retention acceptance. Production remainsOFF; local isolated acceptance explicitly opts in. No external service, alert, scheduled collector or retention policy is installed by this patch. IDs are available in response headers for support/developer tools, not shown in every product screen. Framework-generated404/405/OPTIONS, page/SSR errors and failures after a streamed response has begun are outside this API-handler event; do not claim whole-web tracing. The next observability slice must address page errors and collector supervision.

Validation: unit tests exercise body/context preservation, multiple Set-Cookie values, unique concurrent IDs, returned503/thrown500/HEAD, featureOFF, sink failure, pressure/recovery, streaming and immutable redirects. Coverage test checks each declared API method has one literal-template wrapper; full Next typecheck/build verifies accepted route signatures. Built HTTP and native receipts are recorded under .agent-work/20260911-api-observability/. Existing authorization/financial services were not edited.

Framework basis: [Next.js route handlers](https://nextjs.org/docs/app/getting-started/route-handlers) use Web Request/Response and support streaming. Tests against this repository's pinned Next/Node runtime determine local compatibility; documentation alone is not acceptance.
