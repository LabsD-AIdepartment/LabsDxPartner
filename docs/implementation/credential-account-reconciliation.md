# Credential account reconciliation — D033

The partner account frontend now follows D025: the account is created after an agreed deal through an invitation, using a username/password. Account metadata includes a username, the existing agreement and support information. It does not offer social linking or removal. Historical identity-method records/services remain separate and unmounted; this change does not delete provider data or convert real accounts.

The active AccountAction contract now admits only recovery guidance and logout. Password mutation stays in the guarded identity service. AccountResponse carries partnerId and permissionRevision; loadAccount rejects a foreign user, partner, permission revision or agreement even when agreement data is absent. Development account fixtures follow that contract and no longer fabricate connected Google/LINE/Apple methods.

The existing CredentialAccount form accepts the shared CredentialEnvironment. Without an override it calls the same real guarded HTTP password-change service. The coherent development AccessPreview supplies the memory-only mock implementation. A wrong current password fails; success replaces the mock credential, signs out the session and invalidates outstanding reset links. Shared account/agreements/support cards remain, and the same shell now gives account pages an account heading with no falsely active Overview tab. The standalone account-preview links to the full temporary account journey to test password changes instead of guessing a preset password or calling real auth.
