# Content discovery and financial periods

My content lists the partner's approved catalogue, including retained archived
metadata. Brand and partial title/brand search determine which clips appear.
Publication dates order the list; they do not limit discovery to the selected
income range. Brand options likewise come from that partner's catalogue.

The date range determines published earnings for each clip. No published coverage
or no earnings permission produces null money with a reason. Complete published
coverage with no earning rows produces known zero. Existing partial coverage
remains partial. Catalogue availability never authorizes or fabricates finance.
Stored platform performance remains a separate read and is not commission.

This allows a partner to find an older clip and inspect its newer video metrics
before the newer period's commission has been published. The same list filtering
semantics are used by the preview adapter. Its scenario-based finance fixtures
remain synthetic; they do not prove publication coverage in the native backend.

No response schema, permission, database schema or deployment topology changed.
Native lists retain 50-item keyset batches, query-bound cursors and generation
checks. The UI appends batches automatically without page controls. Existing
unavailable-envelope hiding remains; a known catalogue without finance returns
a partial envelope and visible cards.

Validation on 2026-09-11: eight isolated PostgreSQL integration tests, 21 content
unit/component tests, typecheck and production build including fixture exclusion.
Independent review checked the frozen five-file implementation/test delta. Native
HTTPS browser verification used stored synthetic data: six August clips remained
discoverable for September 1–10 exclusive, with unknown commission. Opening clip 1
then showed 24,000 views, 18 paid SKU orders, 22 items and 21,500.50 THB platform GMV.
No live API, real-account, load-test or deployment claim is implied.
