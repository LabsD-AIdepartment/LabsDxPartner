# Staff import activity

The existing collapsed connection panel now has a separate read-only queue summary. Latest successful import remains a timestamp for the latest success; it does not imply every planned report is current. Each authorized connection can show running, waiting-to-start, scheduled/backoff and attention report counts, plus the earliest eligible retry time.

`GET /api/v1/staff/import-activity` takes the existing actor/revision scope plus `platform=facebook|tiktok`. The shared contract, SQL reader and UI component have no source fetch dependency. Access uses `manage_partners`, matching staff identity/revision and per-connection grants. Existing feature flags apply. The original connections response is unchanged: old clients do not call this endpoint, and new clients retain connection controls if an old server returns404. Missing, failed or mismatched-revision activity is shown as unavailable, never healthy.

Counts describe persisted planned report windows, not a process heartbeat or instantaneous provider execution. Facebook excludes retired periods and inactive mappings/partners/clips; TikTok uses the current revision/calendar schedule and daily windows, excluding older schedules and respecting account access holds. Active leases count as running; expired leases rejoin the waiting/scheduled classification. Next attempts account for per-window backoff, account cooldown and Facebook app/account throttle holds. These categories are disjoint and reconcile to the report count. A paused connection is displayed as paused without a delay advisory.

The server supplies one database evaluation time. Waiting work older than three minutes gets a staff advisory to inspect the collector; three minutes matches the current supervisor no-progress interval and is a diagnostic threshold, not a provider SLA or proof that the worker is down. A busy queue can also cause waiting. This advisory does not auto-retry, notify external channels or request manual approval of ordinary imports. Future cooldowns are scheduled, not overdue waiting. Polling occurs every15seconds only while the existing connection details are mounted; no background-tab polling is enabled.

The endpoint reads indexed windows and aggregates in PostgreSQL; it does not transfer observations, customer records, account secrets, raw provider errors or lease tokens. There is no new table, mutation, credential handling, worker or deployment unit. Reverting the route/reader/component requires no data rollback. Operational correlation IDs, external alerts, log retention/rotation and broader release acceptance remain separate work.
