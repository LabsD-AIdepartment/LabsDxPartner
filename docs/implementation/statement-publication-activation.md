# Statement publication activation — D118

Financial reads and statement publication now have independent deployment controls. Default: LABSD_STATEMENT_PUBLICATION_ENABLED=0. Publication requires exactly 1 for this flag, LABSD_FINANCE_ENABLED and LABSD_IDENTITY_ENABLED. The environment is server-owned; no browser toggle or request field can activate it.

The native POST /api/v1/staff/periods/publish checks activation before constructing identity or the publisher. When closed it returns 503 PUBLICATION_DISABLED, retryable:false, private/no-store. Existing open clients receive an explicit disabled message. When enabled, the original request still passes binding, origin, input size/schema, staff grants/revision, fresh authentication, approved immutable generation and transactional/idempotent publication checks. No money calculation, approval or database schema changed. Internal offline/test service calls are not public activation controls.

The shared staff console receives only the server boolean. Default OFF preserves period search, totals, evidence and existing statements; it shows one explanatory notice and omits scheduling/publication controls. Partner pages and data remain unchanged. Readiness rejects publication ON without either dependency. Deliberate publication OFF with healthy enabled identity/finance remains ready.

Operational use: enable only in an explicitly accepted target after its finance source and release checks pass. Apply consistently to every web instance by restart/redeploy; environment settings are not a hot feature-flag service. Disabling prevents new requests on those instances, but does not cancel already admitted transactions or undo published statements. A code rollback to a version predating this guard removes the control and must be evaluated separately. No production activation is authorized by this local change.

Local checks: 16 targeted unit tests, 7 existing real-PostgreSQL staff finance tests and full typecheck passed. Unit route tests cover default/invalid values, forged client activation, original-request delegation, a later OFF request, readable finance while OFF, disabled-client text and readiness dependencies. Existing PG tests verify real publication and its guards; these are complementary, not a claim of production acceptance. Built HTTP and independent review receipts are recorded in the project context after execution.
