# Page error recovery and framework events

D120 adds a shared Thai failure panel for page rendering and root-layout failures. The user can reload the current URL after the fault is resolved. This is a full page reload, not an automatic retry of financial actions. Normal page layouts and existing domain error responses are unchanged. Both error boundaries use the shared typography (minimum 16px), button, theme tokens, and error-reference formatter. The root fallback imports its own fonts/styles and restores the optional saved theme because the normal root provider is unavailable.

The Node instrumentation hook emits `framework_error` only when `LABSD_WEB_ERROR_OBSERVABILITY_ENABLED=1` (default OFF). It is separate from the API observer flag. Approved metadata consists of UTC time, generated event UUID, exact source-known route template, fixed method/kind/render-source values, and an optional reference derived from a bounded numeric Next digest. Unknown route templates become `unknown`; a unit test detects source/catalogue drift. No request path, query, headers, body, actor, error message, stack, or raw digest is projected into these events.

The `E-` reference is a non-cryptographic 32-bit grouping label, not a unique request ID or security mechanism. Pair it with time, route and event UUID when investigating; collisions and absent digests are possible. The same formatter on server and UI makes a displayed reference searchable in structured events. The hook never changes the error or its digest. The shared bounded writer preserves D119 pressure/drop/error behavior; these events are best effort, not an audit ledger.

This does not redact Next's own stderr or third-party logs. Do not forward arbitrary stderr under a claim that it is sanitized. A collector must explicitly select approved structured events and apply its own retention/access policy. No collector, alert service, scheduler, or production deployment is installed here. Server hooks do not capture arbitrary browser event-handler errors. Error boundaries cover render failures, not all networking/download/event failures; errors after streaming begins need not change HTTP status. No whole-web tracing claim is made.

Validation: 13 focused unit tests passed, including the existing API writer regression tests; clean and isolated fault-injection production builds passed TypeScript and fixture exclusion. In the ignored fault build only, task-local flags simulate login-page and root-layout exceptions. Native HTTPS showed both Thai fallbacks with references matching structured server events, and clicking reload after removing each flag restored the login page. Root fallback retained Dark theme; measured 280/375/1016 CSS widths had no horizontal overflow and button/body/reference text remained 16px. This is responsive geometry evidence, not native 200% zoom acceptance. Screenshot compositing can clip the right edge despite DOM bounds; no pixel-perfect screenshot claim is made. Clean product source contains no fault injection.

Framework contracts: [Next instrumentation onRequestError](https://nextjs.org/docs/app/api-reference/file-conventions/instrumentation) and [error/global-error boundaries](https://nextjs.org/docs/app/api-reference/file-conventions/error). Actual tests use the pinned repository runtime; documentation alone is not acceptance. Detailed local receipts live in `.agent-work/20260911-page-errors/`.
